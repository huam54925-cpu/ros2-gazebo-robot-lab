# 训练工作流与异机设计规范

本文档固化设计机与训练机的分工、镜像边界、错误处理和模型质量观测方式。
以后算法迭代优先按此逻辑扩展，避免验收逻辑和长时间训练混用。

## 机器分工

- **设计机**：拥有完整仿真环境与车辆建模。负责接口、观测、奖励、同步后端、评估脚本的开发与验证。在本机先跑通随机动作审计、短 SAC、固定场景评估后，再打离线包。
- **训练机**：仅提供算力（好显卡）。导入离线包后，启动独立仿真容器 + CUDA 训练容器，只执行已冻结的 `LocalDriveEnv` + SAC。不直接修改算法逻辑。
- 两者之间不依赖网络传输，靠离线镜像/代码包传递。结果（检查点、评估 JSON、关键日志）回传设计机，用完整仿真环境复核。

## 镜像与包规范

- **仿真镜像**：在设计机构建并验证，包含插件与精确步进逻辑。训练机导入后直接使用。
- **训练镜像**：只含锁定依赖 + 代码。CUDA 仅在训练容器内。
- 开发期优先 volume 挂载源码到训练容器，稳定后再重建镜像。
- 每次打包附带源码校验清单和评估脚本，便于两边核对版本。

## 训练运行时错误处理

验收脚本保持失败即停。正式训练循环不包全停外壳，按以下分类处理：

| 类型 | 例子 | 处理方式 | 是否进 Replay |
|------|------|----------|---------------|
| 可恢复基础设施 | 只读状态查询空响应、短暂超时、偶发时钟抖动 | 有界重试；仍失败则本步丢弃、停车、重建后端，继续下一回合 | 否 |
| 正常环境事件 | 到点、超时、停滞 | 正常 terminated / truncated | 是 |
| 不可恢复 | 连续多次重建失败、动作提交后无 ACK 且无法确认状态 | 记录原因，干净退出，保留最后检查点 | 否 |

- 动作提交和物理推进路径不自动重试。
- 只读查询可有界重试。
- 连续失败计数器：超过阈值（建议 3 次回合）才退出。
- 所有基础设施错误写日志 + 计数。

## 模型质量观测

从短训练阶段开始强制以下机制，避免模型问题被长时间掩盖：

1. **周期性独立评估**
   - 每 N 步用确定性策略在固定 seed 场景上跑若干回合。
   - 记录到点率、平均路径长度、超时率、平均奖励。
   - 评估结果写独立 JSON，与检查点一起保存。
   - 设计机收到后用完整仿真环境复跑同一脚本，对比一致性。

2. **关键指标监控**
   - 训练侧：Replay Buffer 大小、最近步平均奖励、策略熵、Q 值均值、动作分布。
   - 仿真侧：每步时间误差、ACK 延迟、重建次数。

3. **固定场景回归测试**
   - 保留 2–3 个固定 seed 的短评估脚本。
   - 大改奖励、网络或动作范围后先跑回归，确认无明显退化再继续长训练。

## 入口区分

- 验收模式：固定短步数，任何关键失败即停，输出完整报告。
- 训练模式：正常 `learn()`，基础设施错误由后端内部处理（停车 + 重建），连续失败才退出。

设计机始终掌握环境正确性，训练机只贡献算力。模型质量问题通过两边一致的评估比较早暴露。

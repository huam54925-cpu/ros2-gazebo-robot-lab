## 1. 持续调查与 MCP

新增 `workspace/robot_skills/investigation.py` 和 `investigation_worker.py`：调查对象、假设、地图 epoch、连续动作、证据和终止结果分别存储。一个调查 ID 可以关联多次导航；失败不会自动删除调查。模型判断保存为 `model_assessment`，不会修改地图或自动成为结构真值。

新能力只在本地启动的两阶段 mission 中注册，旧客户端仍保留原工具集：

| MCP 工具 | 行为 |
|---|---|
| `view_map` | 异步读取在线 SLAM 地图，返回 PNG、未知边界标签、图像到地图坐标转换、位姿和轨迹 |
| `start_candidate_search` | 异步候选搜索，任务状态包含已检查数量；不产生运动 |
| `plan_navigation` | 对多个目标分别从当前位姿查询路径；查询结果不是执行许可 |
| `start_investigation` | 创建 `observe_structure` 或 `verify_passage` 调查 |
| `navigate_to_pose` | 在当前调查内提交任意地图坐标，执行前重新规划和检查 |
| `navigate_through_poses` | 顺序执行途经点，每段重新规划并确认停车；每请求最多 32 个点，可继续提交下一批 |
| `finish_investigation` | 以本地任务证据结束调查 |
| `cancel_task` | 取消本 mission 的非停止任务；取消请求不等于已停车 |

所有异步工作复用已有 `task_id`、SQLite 存储、请求 UUID 和 supervisor。只读查询不计入运动步数或运动失败预算；规划工作失败不能冒充 `NO_PATH`。只读 worker 超时也不会直接关闭 Nav2；无法确认 worker 退出时保留未解决状态。

`navigate_through_poses` 本版通过多次 `NavigateToPose` 实现，**不是直接绑定原生 NavigateThroughPoses action**。每段停车提供明确的阶段证据，代价是连续通行效率尚待测量。

调查完成结果：

- `observations_collected`：有新鲜观测/地图消息证据；不自动宣称未知结构已被可靠分类。
- `passage_verified`：车体包含 padding 从入口线一侧完整到另一侧，轨迹经过指定入口段且停车确认。这里是在线定位证据，最终仿真通行评价仍需独立真值。
- `blocked`：至少两种不同目标/朝向的实际本地失败证据；只表示这些尝试受阻。
- `unresolved`：证据不足，不冒充成功。

## 3. 整场状态与交接

新增显式入口 `workspace/robot_agent/run_investigation.py`，复用现有看门狗和任务执行器。默认整场预算为 80 m、900 s 仿真时间、3600 s 墙钟时间及 12 次运动失败；这些是待仿真评估的初始配置，不是已标定能力。该入口没有固定动作次数限制，旧试验入口保留原限制。

- `classical`：传统策略独立搜索、选点，模型不参与每步评价。
- `ai_investigation`：交接带地图、轨迹、任务历史和剩余预算的快照后，模型持续使用 MCP。
- `stop_confirmation` / `finished`：统一停止、停车确认和归档。

交接依据包括连续低地图增量、重复无进展，或至少两次完整补查仍无候选。重复轮询同一搜索不能积累交接次数；未完成搜索与超时不算探索饱和；不可比较的地图增量不算零收益。分页搜索在相同地图内容下可以完成整个游标范围，最终一页不再永远显示“未完成”。

传统候选遍历当前地图的自由位置，观察距离范围设为 4.5 m；它是观察位置到未知边界的范围，不是机器人必须停留在出生点 4.5 m 以内。AI 新坐标不受该候选集合限制。

## 4. 失败记忆与防振荡

任务终态和记忆事件在同一个数据库事务写入，记录目标、朝向、接近位姿、地图 epoch、失败分类和进展。相同条件下的失败接近使用冷却；换朝向或从不同位置接近可重新查询/执行。地图内容版本变化不会自动清空整个记忆。

防振荡识别无可靠新增观测的 A→B→A→B；新途经位置或通道通过证据可作为任务进展。它影响重复目标资格，不在 costmap 中制造障碍，因此不会禁止沿旧路中转或退回。跨 epoch 的旧目标需要重新建立调查。

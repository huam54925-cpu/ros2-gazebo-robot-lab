# 从定点导航到自主探索与机器人技能

本文是后续设计建议，不表示 Frontier、MCP 或 LLM 已实现。现有证据见 [2026-10-03 实验记录](experiments/2026-10-03/README.md)。

## 当前判断

静态室内的 Nav2 单目标导航基础能力通过：穿通道、绕隔墙、明确拒绝墙内目标、拒绝后继续接受有效目标。二维 SLAM 已完成闭合路线建图和已观测障碍几何校验，但未单独确认回环约束触发、整屋覆盖或全轨迹定位精度。

下一步可以推进经典 Frontier 基线，同时补动态障碍与卡住恢复专项测试。探索层不只是把 unknown 边缘坐标交给 Nav2：它还需要处理机器人尺寸、可达性、过期目标、重复失败、目标取消和终止原因。

## 推进顺序

1. **鲁棒性专项**：执行途中临时挡路、障碍移除、持续堵塞、取消目标。分别记录减速/停车、重规划、恢复动作或明确退出，不把无限重试算成功。
2. **Frontier 基线**：检测 free/unknown 相邻边界，聚类；在已知自由空间中选择有足够车体余量的观察点，做路径可达性检查，优先选择可达的近目标。
3. **信息增益策略**：在相同输入和预算下比较信息收益与路径成本。保留相同的底层导航、安全和终止规则。
4. **可调用技能接口**：先供普通程序和测试调用，再加 MCP 或模型适配器。
5. **LLM 高层决策**：用于任务解释、候选目标选择和失败解释；通过与经典基线对比评估价值。

第一版不引入多智能体，不依赖模型维持停车保护，不给模型暴露禁用保护或任意 shell/ROS 发布入口。

## 技能接口：先小而完整

```text
Frontier 策略 / 任务程序 / 可选 LLM
                 ↓
          统一技能接口
                 ↓
       ROS 2 Actions / Services
                 ↓
          Nav2 / SLAM / 传感器
                 ↓
          独立确定性停车保护
```

| 技能 | 语义与约束 |
|---|---|
| get_robot_pose | 返回 frame、时间戳、位姿和数据是否过期 |
| get_map_summary | 返回地图版本、尺寸、已知/未知数量；没有固定评估区域时不冒充 coverage |
| get_navigation_status | 返回 task_id、状态、进度、错误码与传感器健康 |
| navigate_to | 校验 frame、有限数值、地图版本、车体余量与可达性，异步返回 task_id |
| cancel_navigation | 取消指定 task_id，等待 Nav2 确认；确认停止前不能声称已停车 |
| stop_robot | 高优先级取消活动目标并禁止继续执行旧目标，验证速度归零；需单独实现和测试 |
| return_home | 使用显式保存的地图坐标与定位状态，不能假设 home 永远是 (0,0) |
| save_map | 保存地图与元数据，按需保存位姿图；禁止无意覆盖已有实验 |
| get_frontiers | Frontier 实现后提供候选 ID、观察位姿、可达性、成本及地图版本 |
| explore_next_frontier | 组合技能，在前述原子接口稳定后实现 |

所有运动技能共享一个任务仲裁器，任何时刻只允许一个活动导航目标。请求应有 request_id、超时和幂等语义；网络重试不能重复创建导航任务。高优先级停车需要明确恢复操作，不能仅依赖偶发一次零速度消息。

建议状态机：`accepted → running → succeeded / rejected / aborted / canceled / timed_out`。结果保存原始 Nav2 错误码，同时提供人可读原因。不要把超时、定位失效和 GOAL_OCCUPIED 合并为一种失败。

“目标 cell 是 free”只是必要检查的一部分：还要考虑完整 footprint、到达姿态、膨胀代价、路径连通性和传感器新鲜度。目标在地图变化后可能失效，执行期间仍需要 Nav2 与独立保护。

## Frontier 的停止和失败规则

- 保存目标失败原因；对反复失败的候选进行限次重试或暂时排除，并在地图变化后重新评估。
- 无可达 Frontier 时报告这个事实；不能直接声称整屋已探索完毕。
- 区分 `coverage_target_met`、`no_reachable_frontiers`、`budget_exhausted`、`localization_lost`、`operator_stopped`。
- 仿真真值仅进入评估器，禁止用于探索目标选择和路径控制。

## 统一实验字段

至少记录：run_id、代码版本、配置/地图摘要哈希、场景、策略、随机种子、初始位姿、仿真时间与墙钟时间、实际行驶距离、目标/失败数量、失败原因、恢复次数、最小雷达间距、地图质量指标、停止原因。

Coverage 必须给出固定评估区域和分母定义，并区分可观测区域与机器人可行驶区域。T90/T95 只有在这个定义固定后才可比较；未达到阈值时报告未达到，而非补一个数值。`Δknown / 行驶距离` 在距离为零时不定义。碰撞次数只有接入明确的接触观测后才能报告，不能把“未触发停车”替代为“零碰撞”。

仿真性能先测实时因子与处理延迟，不预先保证 2–5 倍实时。策略对比使用相同初始条件、传感器、导航配置和资源预算，做多次重复实验。接入模型后额外记录决策延迟、调用成本与降级行为。

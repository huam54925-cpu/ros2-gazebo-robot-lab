# 2.0：以持续 AI 操作为主线

## 版本决策

采用 `e354768` 实际运行的决策与动作循环作为 2.0 基础：0.6 m/s 直行目标速度、0.8 rad/s 旋转目标速度、360° 扫描、AI 任意方向选择、当前对应激光束半量程移动。不改成本轮之外的新策略，也不重新引入传统候选审批。首次基线运行源码和每个动作原始文件均保存。

主线删除 154 个旧实现/入口/教程文件。旧内容完整保存在 `archive/pre-v2-2026-10-06`。历史实验目录保留；其中源快照只用于解释历史数据，未加入运行搜索路径。主线不再有传统 Frontier 探索、Nav2 调度、旧 robot_skills 调查/恢复链、velocity_guard 或临时绕过旧保护的程序。

未知边界连通分量仅作为地图标注继续保留，已经从旧探索器抽出为 `map_components.py`，它不生成导航候选、不决定可通行性。

## 当前链路

`run_scan_drive.py → MCP → scan_drive_worker.py → Gazebo 速度话题`

在线 SLAM、激光和里程计提供输入；Gazebo 世界位姿及场景真值仅进入事后评价。MCP 仅含 `scan_surroundings`、`drive_half_visible_range`、`stop_exploration`。扫描由循环自动安排，移动结束自动开始下一次扫描；无三目标上限。

单场记录版本号、运行期限、源码哈希和已解析挂载状态。MCP 请求与容器必须具有相同挂载状态，避免声明关闭但实际启用（或相反）。现有容器必须通过 2.0 入口重新启动才能运行 2.0；本次不重启仿真。

## 约束作为选项

安全挂载接口与决策系统分离。`off` 路径不导入 `mounts`，不执行车体、地图、障碍净空或安全停车判断。`on` 延迟加载独立 `mounts/lidar_sweep.py`，只对收到的激光回波做当前车体与短时恒速扫掠检查，记录拒绝点与预测时刻；没有传统选点、恢复审批或全路径 veto。

该挂载使用原车体六边形，2 cm 额外余量、0.5 秒预测窗口和 21 个离散姿态，保留激光外参及扫描接收时里程计的运动补偿。扫描与里程计不是精确时间插值同步；离散点和恒速预测有盲区。模块不能被描述为已验证的完整避碰能力。挂载拒绝时本场按动作失败结束，尚未设计新的自动恢复策略。

`auto` 是可复现的环境规则：Gazebo 实验自动关闭；其他环境的纯策略函数返回开启，但实际执行器只实现 Gazebo，不会据此执行实车任务。不要把自动策略描述为模型已判断环境安全，也不承诺实时切换。

## 后续开发原则

优先提升连续行动、覆盖结果、决策效率和可解释数据。安全约束默认不进入 Gazebo 基线；后续新增或保留约束应有可测收益，优先减少重复、保守或不必要的约束，允许独立关闭和对照。不给本次无约束数据补上不存在的安全验收结论。

本次数据暴露的问题用于后续版本：里程计成功与真实到达不一致、整圈扫描有时移动位置、API 断线结束循环。整理版不改变这些已观测的决策/运动行为，以保留可比基线；没有用 Gazebo 真值替代 AI 输入或控制反馈。

## 本次整理验证

6 项挂载/独立地图渲染测试、4 项半量程/MCP 测试、4 项 API 配置与错误脱敏测试，加保留的覆盖率与扫描适配测试。Python AST 和 shell 语法检查。首次运行覆盖测试缺少 `PYTHONPATH=workspace` 导致导入错误，补齐测试运行环境后重新验证。未进行模型调用或新的运动仿真。

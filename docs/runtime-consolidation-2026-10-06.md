# 主运行路径整理与恢复修正（2026-10-06）

基于 `e1663f5` 继续修改。用户后续明确授权“完成修改后，运行测试和完整仿真”，因此本轮已执行回归测试，并启动 Gazebo、SLAM、Nav2 和两阶段任务。下面区分代码实现、实际运行结果及未解决的能力边界。

## 清理旧入口

原系统的新入口仍从旧 `run_loop.py` 取得会话管理，执行器仍继承单步试验 `motion_worker.Trial`。本次拆出真正共用的部分：

- `mission_session.py`：仅负责两阶段 mission、MCP、心跳、看门狗、取消与最后停车。
- `action_lifecycle.py`：保留动作归属、迟到接受响应和 Nav2 生命周期暂停，不包含独立运动试验。
- `map_feedback.py`：保留在线地图快照和观测收益，不再包含旧的观察候选/旋转动作入口。

删除旧 MOVE/STOP 循环、单次候选模型调用、单步运动 MCP/CLI、观察动作执行器及仅针对这些入口的测试和重选回放。相应历史版本仍在 Git 中。当前入口：

```bash
# 正式两阶段入口；初始化扫描是单独记录的前置观测
scripts/robot-investigate.sh --ai-reserve-fraction 0.3
scripts/robot-skills.sh state
scripts/robot-skills.sh stop
```

`robot-skills.sh` 现在只提供状态、任务查询、停止和显式操作员恢复管理。无 mission 的 MCP 仅注册状态/任务查询和停止；传统 frontier 执行只在两阶段 mission 内注册并限于传统阶段。旧 `fixed_step` / `perform_observation` 请求在入库和启动 worker 前被拒绝。

仍被新系统调用的地图几何、规划、观测收益、区域统计、任务存储和安全工具保留。历史日志和实验源快照未清空；旧预算读取/审计工具不作为新系统入口。删除旧入口不等于删除共用导航库。

## 短退逐级缩短

短退先根据真实 odometry 直线后缀得到历史上限，然后在上限内按 5 cm 递减检查。例如历史允许 20 cm 时，检查 20 / 15 / 10 / 5 cm；历史只允许 13 cm 时，检查 13 / 10 / 5 cm。每步重新检查地图、补偿后的扫描和制动余量，执行前再复核一次。

一个失败来源仍只消耗一个恢复资格；距离选择中的几何拒绝不是多次运动。完整记录 `history_limit_m` 和 `shorter_step_checks`。反馈失效、停止或预算错误会直接退出，不作为“换一个更短距离继续试”的理由。

## 仿真时间与墙钟分别判断

短步无进展按 **5 仿真秒** 判断，动作时限按距离/速度加余量计算。独立墙钟保护为：时钟连续 **10 墙钟秒**不推进则失败，单短步最终等待上限 **180 墙钟秒**，且不能越过整场墙钟截止时间。通用导航的 40 秒墙钟无进展检查不再套用短步技能。

因此 20 cm、0.04 m/s 的理想 5 仿真秒动作，不会仅因经过 30 墙钟秒就被判失败。任意慢速仿真仍不保证无限等待：总预算、反馈失联和最终墙钟上限继续有效。

同时拆分接收活性与测量时间：footprint 保护下扫描/odometry 接收失联上限为 5 墙钟秒，测量时间新鲜度仍按 0.5 仿真秒检查；命令为 0.5 仿真秒或 5 墙钟秒任一到期即停车。命令时刻以本地接收时的 ROS 仿真时钟记录。这些参数统一进入车辆契约，旧进程哈希不匹配时拒绝新任务。本轮使用隔离工作副本和独立任务数据库启动了匹配配置的运行进程。

## AI 资源预留

`--ai-reserve-fraction` 默认 0.3，在整场总额度内预留时间、距离和失败次数，失败次数向上取整且至少 1 次。传统规划派发不能使用预留的仿真时间/距离；传统任务和查询在资源边界停止，确认停车并取得快照后交接。

候选不再符合传统可用预算时交接 AI，不再直接宣布整场结束。交接记录区分：

- `exploration_progress`：持续低收益、无进展或充分搜索后缺少候选。
- `resource_reservation`：传统资源边界已到，或下一动作会占用 AI 预留额度。

预留不扩大总预算，也不允许覆盖停止锁、反馈错误或整场截止时间。交接本身仍需要工作正常的地图、反馈和停车确认。

## 失败证据

字符串标签只用于诊断。`blocked` 需要本地规划器明确无路结果或地图完整车体扫掠受阻证据，并要求停车确认、同一调查/epoch 和不同尝试目标。规划器的 TF、内部错误、超时等不会被合并成“无路”。

配置、定位、传感器、取消、预算或不明原因失败应为 `unresolved`，不能凑够两个目标就宣称受阻。旧失败记忆也不能仅凭字符串将目标冷却；需要路线层面的证据。真实原始结果继续留存，供后续分析。

## 扫描运动补偿

新增 `scan_motion.py`。使用带时间戳的 odometry 插值，把扫描采集时的激光点转换到当前 odometry 对应的车体坐标；如果 `time_increment` 非零，按每束激光时间补偿。平移和转向都纳入变换。

速度保护和短步检查共用这个实现。缺少采集时位姿、插值间隔过大、frame 错误、时钟回退或反馈过期时拒绝运动，不以扩大预测时域代替坐标补偿。补偿后的剩余 odometry 时间差仍计入运动预测。该方法依赖在线 odometry 与近场障碍在扫描间隔内的观测，不声称提供动态障碍真值或完整遮挡重建。

## 仍然明确保留的边界

当前姿态已经侵入必要保护余量时仍停车。接触、挤住后放宽起点间距、曲线路径倒退或接触式姿态恢复没有在本轮实现，不把删除保护条件冒充脱困能力。

规划器仍为 SmacPlanner2D；本轮没有接入 State Lattice。中心线规划加车体复核仍可能拒绝需要其他朝向轨迹的通道。后续完整仿真的覆盖率、恢复后持续探索效果和拒绝原因才能说明这些改动是否有效。

## 回归测试与运行适配

修改了原有调查/恢复/协议/存储回归源码，去掉恢复测试继承导致的重复用例；增加短退步长、慢仿真时钟/停钟、预留交接、系统故障不能作为 blocked、扫描平移/旋转补偿与缺失历史的用例。回归已执行；同时在导航容器中执行只使用 ROS 类型、不会启动运动的执行器测试。具体计数和仿真结果见下方运行记录。


### 实际启动中补齐的部分

- 容器以普通用户启动时，继承 `/dev/dri` 对应设备组；无交互终端也可启动。新增 `ROBOT_HEADLESS=true` / `headless:=true`，可只运行服务端、桥接与保护链。
- X11 会话重新登录后应先执行 `docker/prepare-display.sh` 更新本地显示授权；旧授权会使 GPU 雷达退到失败的 EGL 初始化。授权文件不进入 Git。
- 共用 `sensor_offset()` 移入 `map_feedback.py`，删除旧观察模块后仍能查询雷达外参；增加执行器回归。
- Nav2 动作端点出现早于生命周期激活。执行器最多等待 30 秒激活，并在等待中响应取消，不能把“端点存在”等同于“规划器可执行”。
- Spin 的速度/加速度也从车辆契约生成；任务运行前核对行为服务器的旋转速度和短步最低速度。
- 空白地图仅收到首个 SLAM 关键帧时，可通行地图过于稀疏。新增显式 `scripts/initialize-exploration-map.sh`：验证恢复状态后，只执行受 Nav2 碰撞检查和实时 guard 保护的初始扫描，确认停车。扫描时限使用该段明确的墙钟预算，初始化观测单独记录；它不是 AI 调查，不算通道通过。

### 覆盖率口径

`diagnostics/coverage_monitor.py` 是只读评估器，不被探索器或 MCP 导入。当前仅适配 `indoor_mapping.sdf`：固定室内范围 24 × 20 m，扣除雷达高度上的静态盒状障碍，固定自由空间分母 **465.5 m²**，采样间距 5 cm。地图未知、地图外部以及被地图判作占据的参考自由单元均不计入已观测自由覆盖。

使用初始车轴建立的标称地图到场景配准；没有利用真值纠正在线地图。配准漂移可能影响百分比，因此报告称为“标称配准自由空间覆盖率”，不能当作独立地图精度验证。地图画布扩大不改变分母；初始化、交接和终态分别取样。该评估器不证明无碰撞或整车穿过通道。参考场景几何和评估结果不提供给模型或导航决策。

参数语义依据 [SLAM Toolbox 官方说明](https://github.com/SteveMacenski/slam_toolbox)：`min_pass_through` 控制单元成为已知所需的射线通过次数。本轮保留原值 2，通过实际扫描取得新观测，不把未知直接改成自由。


### 扫描同步与候选计算中的取消

实际短退曾在 7 mm 左右因 `scan_pose_history_unavailable` 停止：扫描比同一时段的里程计先到达。短步执行器现在固定一帧扫描，在 5 秒接收活性上限内等待真实的里程计插值区间，且只允许 0.2 仿真秒内的正常到达次序差；不追逐不断更新的新扫描，不外推位姿。等待期间 guard 继续独立停车/验证；取消立即生效。等待结束后，用当前位姿重新检查地图扫掠。缺失历史、长缺口或超时仍是基础设施问题，不能当作通道受阻。

候选生成的周期回调在排空 ROS 反馈后也检查任务取消和资源边界，避免长计算绕过停止请求或 AI 预留预算。

### 停车取证与实际界面

运行中保持 Gazebo 和 RViz 打开，未因查看界面停止或重启仿真。新增只读 `diagnostics/stop_evidence.py`，订阅扫描、odometry、原始/受保护速度和 `/rosout`，保存停车前的带时间戳上下文与实时 guard 记录。它不发布运动指令，不修改车体或碰撞检查。

记录包含触发组件/原因、补偿后的障碍车体坐标、到未膨胀车辆契约轮廓的距离、guard 扫掠预测位姿/命中证据，以及记录时间差。测量间距是雷达观测值，不是仿真真值；Nav2 日志没有暴露碰撞命中点时明确保留 `null`，不能把独立复算冒充原组件的碰撞判据。

初始化扫描期间捕获到短暂速度归零：`velocity_guard` 报 `footprint guard invalid input: ValueError`，同时附近采样的最近障碍距未膨胀车体约 2.74–2.80 m，独立扫掠复算为 clear。这是保护输入异常的证据，并非近障碰撞证据；该运行版 guard 把具体异常归并为 ValueError，尚不能据此确定是哪一项输入。记录器后续另存最新扫描补偿异常和里程计时间戳，以便进一步定位。

本轮冷启动第一次 Spin 返回错误 703 `Collision Ahead`；随后同场重试完成全圈扫描并确认停车；重试过程中查询到的局部代价地图车体检查为 clear。第一次拒绝时的 Nav2 命中点没有取得，不把“重试成功”当作根因已修复。初始化成功回合用时约 239 墙钟秒，初始化观测单独记账。

### MCP 参数结构与可恢复错误

模型实跑创建调查时重复漏传 `subject.yaw`：原 schema 仅声明任意浮点字典，没有枚举必需键；底层 `finite_pose` 要求 x/y/yaw，而 MCP SDK 将普通 ValueError 隐藏为通用工具执行失败。模型读不到 `pose_requires_x_y_yaw`，无法据此修正请求。

现在调查主题、导航目标、路线查询和途经点共用显式 `MapPose` schema：x/y/yaw 均为必需字段，拒绝额外属性。预期的本地 ValueError 规则代码通过 `request_rejected/reason` 返回；非规则异常仍交给 SDK 处理。新增协议回归验证缺失 yaw/额外速度字段被拒绝，以及本地规则失败不再被隐藏。协议组更新为 17 项，连同 93 + 19 + 1 项，累计 **130 项测试通过**。

加载新 schema 需要新任务客户端。已结束出现接口重复拒绝的任务，保持 Gazebo、Nav2 容器、地图和界面不重置，再启动同场景端到端回合。前一轮是人工结束的调试回合，不算完整探索成功；两次起始状态/预算也不构成严格对照。

### 600 秒端到端回合与停车证据

回合 6 跑到 `max_wall_time` 并确认停车。模型成功创建同一个调查、比较接近路线、提交 3 次坐标导航，受阻后重新查路，并申请前进试探。3 次导航均因 `body_sweep_nonfree` 中止，不能算目标到达；前两次自动短退分别约 8.10 cm 和 6.07 cm，Nav2 返回成功。试探实际产生位移，但最终报告 `short_motion_endpoint_not_reached`，不计成功。

累计里程（含退回和试探）约 1.1004 m。固定分母的标称自由空间覆盖率由 **27.6015% → 27.7750%**，增加 **0.1735 个百分点**。初始化的观测已包含在起始值中。本回合后段按用户要求切换了碰撞保护策略，因此这个增量不是正常保护模式的性能验收，也不能归因于模型的独立贡献。

第一次导航的冻结快照给出具体拒绝：当前 map 位姿约 `(0.171, 0.176, 0.589 rad)`，复核预测原地转到 `2.630 rad` 时，车体距一个未知栅格仅 0.0648 m，小于 0.075 m 余量。该格是 `-1`，不是已观测障碍。附近雷达样本距真实契约轮廓约 3 m。按配置的 0.65 m RPP 前视距离离线求交，目标方向误差约 0.312 rad，小于 0.50 rad 原地转向阈值；这是配置/路径的离线推断，不是捕获到的 Nav2 carrot 输出。证据说明自定义预测与控制器轨迹可能不一致，尚未修改这个预测算法，也没有据此认定通道不通。

### 用户授权的临时 Gazebo 诊断模式

用户在实跑过程中明确要求“先暂停所有关于安全方面的停车和阻碍车辆运行的程序，让他继续探索，不要一直停下来改”。据此增加**默认关闭**、只在当前 Docker 仿真且有未过期操作员标记时启用的诊断模式：

- 暂停原 `velocity_guard` 进程（SIGSTOP），由 `gazebo_diagnostic_relay` 转发限速后的速度命令。不能直接退出原 guard，因为现有 launch 会因此关闭 Gazebo。
- 设置 Nav2 RPP `FollowPath.use_collision_detection=false`，跳过额外地图车体扫掠/姿态复核和激光扫掠；后续短步 action 显式标记碰撞检查暂停。
- 保留正常路径规划、当前速度范围、有效指令/里程计活性、操作员停止及整场预算。规划器仍使用地图寻找路线，不把墙变成自由空间。
- 证据标记 `collision_checks=false`、`safety_verified=false`；这类结果不能冒充正常模式的安全/通道验收。

本次显式诊断窗口为 1800 墙钟秒，标记保存在忽略的 `workspace/log/gazebo-collision-bypass.json`，不上传仓库。relay 正常结束或窗口到期时恢复 Nav2 碰撞检测并继续原 guard。它不是新的默认运行模式，也不是模型可调用的开关。新增 3 项作用域、到期和证据语义回归；累计 **133 项测试通过**（96 + 17 + 19 + 1）。

回合 7 沿用当前世界与地图继续运行：900 秒墙钟、600 秒仿真时间、80 m，AI 预留 70%。不重置仿真，不在该回合中继续调安全策略。其结果须按“碰撞保护暂停”的诊断回合单独解读；记录生成时仍在运行。

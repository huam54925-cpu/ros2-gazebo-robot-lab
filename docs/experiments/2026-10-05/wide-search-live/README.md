## 计时与第二轮停止原因

| 第一任务阶段 | 仿真秒 | 墙钟秒 |
|---|---:|---:|
| 规划前验证、规划、执行前复核合计 | 4.285 | 12.034 |
| 导航，含转向 | 43.505 | 120.043 |
| 停车验证合计 | 1.398 | 1.406 |
| 地图反馈等待 | 4.008 | 8.148 |

初始反馈等待约 5.788 墙钟秒，在任务窗口外，仿真时长未知。阶段 ROS 时钟受回调更新时间影响；导航里程计可分类的连续时间仅约 10.166 秒，远小于 43.505 秒导航窗口，不能将分类项拼成完整平移/转向分解。

两轮目录生成耗时 **73.577、71.271 墙钟秒**，目录及上下文期间消耗约 **28.229、33.162 仿真秒**；模型分别耗时 **9.697、10.084 墙钟秒**。这些成本不包含在单动作预算里，明显影响会话剩余时间。

第二轮目录 `1dc033d18832` 又提供 3 个安全候选。决策前剩余 **51.698 仿真秒**，模型选中预算 **48.779 秒**的 1.570 m 直达目标；模型和刷新反馈后只剩 **47.182 秒**，执行前复核拒绝，**没有第二次运动提交**。

另一候选预算 **34.609 秒**、路径约 **1.413 m**，仍满足当时的时间上限。当前循环在所选动作失去预算时直接结束，没有重新请求模型改选。因此原日志的 `no_action_fits_remaining_budget` 过于宽泛，不能解释为所有候选都不合预算。见 [补充预算分析](postrun-budget-analysis.json)。收尾后已将后续运行标签修为 `selected_action_no_longer_fits_after_model`，并记录仍合时间的其他 ID；原实跑日志未改写，没有自动改选或追加运动。

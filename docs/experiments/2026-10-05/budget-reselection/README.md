## 修复内容

模型返回后重新读取当前候选目录、地图版本、预算、停车锁和反馈状态。目录过期或地图改变则重新生成；已消失的 ID 不能执行。若所选动作超预算但仍有合资格候选，预留重选时间，再由原选择器重新选择。模型模式没有经典策略后备。

`--max-reselections` 可设 0、1、2，默认 2：每个待执行动作最多三次决策请求，连接失败后的新上下文轮次也计入上限。被丢弃的选择不提交运动任务。重选预留为 `max(2 s, 1.25 × 上次决策及刷新仿真耗时)`，是显式启发式，不是延迟保证；每次返回后都再检查。

每次尝试记录 selector、候选集合、选择、前后预算、目录刷新原因/耗时和验证结果。原因区分如下：

| 情况 | 记录 |
|---|---|
| 所选动作超预算，但可能存在其他候选 | 尝试级 `selected_action_over_budget` |
| 所选 ID 已失效 | 尝试级 `selected_candidate_no_longer_valid` |
| 当前目录合资格候选均超预算 | `all_candidates_over_budget` |
| 动作可容纳，但再加重选开销后无法容纳 | `insufficient_time_for_reselection` |
| 已到重选次数上限 | `reselection_limit_reached` |
| 执行器最终规划后预算不足 | 任务级 `revalidated_action_over_budget` |

执行器在重新规划、车体/雷达复核后，还会检查重算动作预算和路径长度是否满足剩余会话时间、距离；不通过就不发送 NavigateToPose。此检查保守地使用完整动作预算。1.9 m guard、2.15 m 路径要求、单段 8 m、memory 最多三任务及首步正增量验收保持不变。所有“全部候选”表述仅针对当前目录的合资格采样点，不证明整屋没有其他机会。

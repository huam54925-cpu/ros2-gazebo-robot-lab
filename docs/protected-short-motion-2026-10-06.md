# 第 3 项：低速小步试探与短退脱困（2026-10-06）

本次继续实现两阶段探索方案中的底层恢复能力。**只编辑代码和做静态检查，没有执行单元测试、模型调用、ROS/Nav2/Gazebo、导航动作或进程重启。** 以下参数是待端到端仿真验证的初始值，不代表通过了运行验收。

## 行为变化

以前，导航停滞或路径失效后只返回失败。现在，两阶段任务中已发出动作且有明确可恢复失败原因时，执行器先取消并确认停车，再尝试一次受保护短退。成功后刷新观测、查询到原目标的新路线，把结果交回持续调查任务；原导航任务仍保留失败状态，后续必须重新规划或换接近方式。不会直接自动前进再次顶推。

恢复适用于本地无进展、Nav2 明确的 Failed to make progress、保护扫掠受阻及路径几何失效；通用 Nav2 错误、定位/传感器失效、预算耗尽、取消和停车未确认均不授权短退。没有最近直线路径时返回受阻原因，不推测后方可通行。已暂停的 Nav2 不会被自动恢复。

## MCP 能力

| 工具 | 输入 | 本地行为 |
|---|---|---|
| `probe_forward` | 调查 ID、地图 epoch、请求 UUID | 沿当前朝向尝试 20、10、5 cm 中通过检查的最长一步；按执行反馈继续观察 |
| `recover_short_reverse` | 上述字段加失败来源 task ID | 仅允许同一调查内最近已停车的合格失败；自动恢复已消耗的来源不能再试 |

两个入口都立即返回 task ID，复用异步任务、幂等请求、取消与停止锁。只在两阶段 AI 调查中暴露；传统阶段的导航失败也可调用同一底层自动恢复。速度和距离不由模型填写，额外参数会被拒绝。调查关闭、epoch 改变、其他任务占用、停止锁定或反馈不完整均不能派发动作。

## 底层检查和执行

1. 检查当前契约、Nav2 behavior 参数、实时反馈、停车及整场剩余预算。
2. 试探沿当前车头方向；短退依据刚经过的真实 odometry 直线后缀选择距离，不能把弯曲轨迹假设为可直接倒退路线。
3. 用最新地图检查完整车体固定朝向扫掠及末端制动余量，未知/不确定占用不当成自由空间。倒退不人为增加 180 度旋转。
4. 使用最新激光同时检查拟执行方向与实测运动的制动扫掠；当前车体已侵入必要余量时，仍然不放行。
5. 通过 Nav2 `DriveOnHeading` / `BackUp` 执行，保留碰撞检查，仍走 `/model/vehicle/cmd_vel → velocity_guard → /model/vehicle/cmd_vel_safe`。不发布原始速度，不接触式蹭墙。
6. 动作中持续检查地图、激光、里程计、方向偏差、运动距离、无进展、整场预算和取消。迟到的 action 接受响应也必须取消；最终停车由统一流程确认。

后方检查使用同一车体和安全余量。前方预测扫掠有障碍而倒退扫掠可行时，可以短退；这不是“前方报警就禁用全部方向”，也不是关闭保护。

里程计后缀保留 frame 和仿真时间。运动采样间隔超过 0.5 s、frame/时间异常、历史过旧、曲率超限或前段倒退都会截断可用路线。显式跨 worker 恢复仅能连接来源任务末尾和当前 worker 开头都已确认停车、位姿一致的边界；不合成运动路径或伪造时间戳。整段后退仍必须通过当前地图和扫描复查。

## 参数与预算

参数统一存于 `workspace/navigation_base/config/robot_contract.yaml` 的 `short_motion`：

| 参数 | 初始值 |
|---|---:|
| 试探/短退速度 | 0.04 m/s |
| 前进可选步长 | 0.20 / 0.10 / 0.05 m |
| 短退最大距离 / 最小有效步长 | 0.20 / 0.05 m |
| 航向偏差 / 横向偏差上限 | 0.10 rad / 0.03 m |
| 端点位置容差 | 0.02 m |
| 单动作墙钟超时 / 无进展超时 | 30 / 5 s |
| 每场恢复总次数 / 同位置次数 | 8 / 2 |
| 同位置判定半径 | 0.75 m |
| 同位置同朝向试探冷却 | 30 s |
| 轨迹最大历史时长 | 180 s 仿真时间 |

每个失败来源只消耗一次恢复资格。资格在派发前以 SQLite 事务持久化；检查拒绝、进程中断及更换调查 ID 均不能重置次数。恢复距离和耗时计入原任务及整场预算，不额外赠送预算。停止/取消会阻止资格申请和动作派发。

Nav2 behavior 的最低速度和制动参数从契约派生，防止默认最低速度高于请求的 0.04 m/s。契约哈希已改变，旧运行进程不具备新参数时会拒绝新动作；本次未切换或重启这些进程。

## 反馈和防振荡

任务结果增加 `probe`、`recoveries`、`automatic_recovery_blocked_reason`、`recovery_replan`、`odom_trace`；整场保存 `recovery_attempts`。记录原始失败、恢复来源、地图 epoch、次数、几何检查、实际距离、耗时、动作终态和停车结果。

恢复成功不会覆盖原导航失败；试探/短退成功不算新目标到达，不制造通道通过证据。可靠的新观测仍可计入地图进展。AI 可读取恢复历史、失败原因与剩余策略；密集 odometry 仅留在本地审计，不整段塞入模型上下文。

`motion_trial.xml` 补上 ComputePathToPose / FollowPath 的错误输出，避免控制无进展原因在行为树中丢失。统一停止工具增加 backup 和 drive_on_heading 的取消请求；存在其他活动 behavior 时拒绝新任务。

# 导航、实时保护与探索决策系统改进方案

日期：2026-10-05  
状态：修订后的实施方案，计划于 2026-10-06（Asia/Shanghai）推进整体改造与多轮完整仿真。本文发布不代表运行代码、配置或安全逻辑已切换。  
审查基线：[aca2bde](https://github.com/huam54925-cpu/ros2-gazebo-robot-lab/commit/aca2bde014f2d1ac7e005b1b76c1a38f4a3a05b5)。

## 1. 目标与结论

目标是扩大合法路径上的探索能力，让车辆能够持续导航、遇到暂时问题后有界恢复，并准确解释停止原因。保留最少且可验证的硬约束：真实车体与必要误差包络不碰撞、运动可执行、所需自由空间已确认、反馈有效、指令受控、操作员停止始终有效。

当前问题不是单纯缺少探索意愿。候选粗筛、假设转向、实时保护、地图版本一致性、接口限时及信息收益被叠加为运动前置条件，出现“底层有可行路径，上层未能提供或执行目标”的情况。重构应统一安全依据并明确职责，避免继续增加相互不一致的阈值。

监控从固定大圆距离规则迁移到车体与运动相关的实时保护，监控始终运行。Nav2 规划器和控制器的在线碰撞检查必须保留；Collision Monitor 是独立保护层，不能替代规划可行性、局部轨迹检查或未知空间准入。

本轮采用整体改造、完整回合运行、按结果修复的路线，不再把每个局部动作的逐项验证作为串行交付阶段。最终地图探索覆盖率是主要结果指标，安全与运行完整性是结果有效的前提；不承诺未经实验的性能或覆盖率。

## 3. 职责分层与两阶段探索

| 层级 | 组件 | 负责 | 输出 |
|---|---|---|---|
| 感知与状态 | 雷达、里程计、TF、SLAM Toolbox | 在线地图、位姿、时序与健康状态 | 带坐标系、时间戳与质量状态的数据 |
| 实时保护 | Collision Monitor、watchdog、停止仲裁 | 实时减速、停车、反馈失效处理 | 共用保护链、触发原因 |
| 导航 | Nav2 规划器、控制器、行为树 | 路径、跟踪、在线碰撞检查、有界恢复 | 进度与结构化结果 |
| 前期探索 | 传统 Frontier 算法 | 独立搜索、选点、连续探索、目标记忆 | 地图及剩余未知结构 |
| 后期探索 | AI + MCP 操作接口 | 观察地图、提出目标/途经点、持续执行残余探索任务 | 多轮导航操作与任务记录 |
| 任务管理 | Robot Skills、存储与 supervisor | 阶段交接、任务仲裁、异步操作、预算、取消 | 可追踪的整场任务 |

**前期不加入模型逐步选点。** 传统算法先发挥其连续探索能力，搜索范围不能继续局限于出生点附近。切换依据是持续低增益、重复无进展，或充分搜索后缺少有效目标；不能因为一次候选为空、接口超时或执行三个点就交接。这些条件表示传统阶段趋于饱和，不表示整个环境已经探索完整。

**后期交给 AI 执行持续的残余探索任务。** 交接当前在线地图、地图图像、坐标变换、轨迹、已到访区域、剩余未知边界、失败记录和剩余预算。保留本轮 SLAM 状态，不重置为全图，也不导入仿真真值。模型根据图像和结构化观测提出可能遗漏的结构，通过地图查询与路径工具核实，再提交目标或途经点；不局限于传统算法已生成的候选 ID。

模型的职责从反复判断“是否值得继续探索”转为“怎样执行剩余探索任务”：尝试接近遮挡边界、绕墙端、穿过可行通道、到另一侧观察，读取执行反馈后继续操作。指定任务不能因为中转点即时信息收益为零而被取消；临时失败应先采用有界恢复、重新规划或替代目标。

AI 可以提出新的目标和路径偏好，但不计算实时碰撞、不签发运动许可、不修改保护参数、不解除操作员停止、不绕过速度保护链。图像上的未知结构只是待核实假设，不能据此把未知格改成自由空间。所有操作经同一底层导航与保护逻辑执行。

取消固定三目标/三动作上限。两阶段共用显式整场时间、距离及恢复预算，额度由运行配置确定并记录；这不等于无限运行。模型调用不阻塞局部控制和实时保护。

## 4. 统一判定与保护规则

### 4.1 单一参数源

拟新增 workspace/navigation_base/config/robot_contract.yaml，作为配置生成与校验入口；该文件路径是实施计划，不是当前已经存在的运行配置。

集中描述车体多边形及参考坐标、运动模型、已验证速度与加减速度范围、传感器坐标关系、时间基准、保护所需误差与时延预算。生成 Nav2、监控、任务接口及离线验收所需参数，并记录 contract_version 与摘要哈希。

物理参数共用，但各层派生的判定不同：车体碰撞包络、路径偏好代价和速度相关停车区有不同用途，不能继续统一成一个距离常数。不得把定位协方差直接等同于可靠误差上界；应结合对照轨迹与时序实测标定。

按既有配置，最大车宽约 1.92 m，另有每侧 0.05 m padding，直行名义宽度至少约 2.02 m，尚未含其他跟踪误差。因此 2.0 m 通道不应被要求通过。低速能减少制动相关余量，不能缩小车体或消除定位误差。

### 4.2 硬约束与软偏好

| 内容 | 处理方式 |
|---|---|
| 车体及必要误差包络与障碍相交 | 硬拒绝，由规划、控制与保护共同覆盖 |
| 运动模型不可执行或旋转时车尾碰墙 | 硬拒绝对应动作，寻找其他轨迹 |
| 所需运动包络侵入未确认自由空间 | 不执行该段；重新观察或选可确认的接近目标 |
| 靠墙、转向次数多、路线较长 | 在合法轨迹中用代价评价 |
| 中转点即时信息收益低 | 与远端可达信息、成本和任务目的比较，不作为几何拒绝 |
| 地图版本变化 | 触发相关复核或重规划，不单凭版本不同永久作废 |
| 查询接口等待超时 | 返回等待状态或传输错误，不等同于无路径 |
| 任务明确预算耗尽、操作员停止、反馈失效 | 对应终止或停车，保持结构化原因 |

未知不是确认障碍，也不能默认为可行驶自由空间。地图尚未确认的部分可以成为观察对象，车体不能凭空穿入未知区域。

窄通道中不默认调用原地旋转恢复；若具体旋转运动包络通过检查，可允许相应角度。禁止的是不可行的动作，不是区域名称或所有转向。

### 4.3 Nav2 与实时保护

优先评估 Smac State Lattice 的差速控制集与完整车体碰撞检查。选择理由是该车辆非圆形且存在参考点偏置，需要位置、朝向和运动模型共同参与规划。先保留 Regulated Pure Pursuit 作为控制基线，验证它对规划动作的跟踪一致性；控制器选择与跟踪差异在整场轨迹和日志中记录，依据实际失败修正。

采用 inflation 代价引导合法路径居中，保留碰撞相关的不可通行条件。不能将所有膨胀成本软化，也不能靠提高 inflation 参数保证窄通道通过。

Collision Monitor 使用原始实时扫描和正确 TF，评估多边形停车区、速度相关区域与基于预计碰撞时间的减速。必要保护同时覆盖旋转时车尾扫掠、倒车与传感器盲区。保护参数由制动、时延、定位及跟踪误差标定；不直接沿用示例默认值。

保持操作员停止、命令失效停车、传感器/TF 失效处理及单一速度输出仲裁。控制器与恢复行为必须经过同一保护链，防止任一路径绕过监控。停止确认结合取消终态与新鲜速度反馈，不能仅发送一次零速度就报告已停。

现有自定义精确检查先用于对照。仅当 Nav2 配置与控制轨迹已证明覆盖对应约束后，才将重复在线硬门降为只记录结果的影子检查；若存在缺口，应保留范围明确的检查或实现标准插件。任何切换都要记录新旧判定分歧，不能留下未知空间或整车运动的保护空缺。

## 5. 异步任务与可恢复流程

### 5.1 接口契约

现有运动执行已经有 task_id、幂等和任务存储，优先复用，不重新创建另一套任务系统。新增异步候选搜索，消除候选完整检查占用一个长时间同步 MCP 请求的问题。

| 拟定接口 | 输入概要 | 输出与语义 |
|---|---|---|
| start_candidate_search | request_id、mission_id、搜索范围与资源预算 | 立即返回 search_id，后台增量工作 |
| get_candidate_search_status | search_id | 阶段、已查/待查数量、候选、搜索是否完成 |
| view_map | mission_id、窗口或分辨率 | 当前地图图像、坐标转换、未知区域与地图版本 |
| plan_navigation | 当前姿态、目标/途经点、地图上下文 | 路径及结构化规划结果；不触发运动 |
| navigate_through_poses | request_id、mission_id、途经点 | 异步 task_id，底层规划与执行 |
| recover_navigation | task_id、允许的恢复方式 | 受保护且有预算的恢复，不解除操作员停止 |
| submit_navigation | request_id、mission_id、goal_id 或已授权的指定目标 | task_id；接收不代表许可或成功 |
| get_task_status | task_id | 状态、阶段、进度、健康状态与失败详情 |
| cancel_task | task_id、request_id | 取消请求状态，最终确认另行查询 |
| stop_robot | request_id | 高优先级停止并禁止旧任务继续输出；确认停止后返回证据 |

上述名称是设计接口，需与现有 API 兼容映射。指定坐标导航仅面向本地授权任务；后期 AI 获得任务授权范围内的新坐标目标和途经点提交能力，不限于候选 ID；坐标系、地图上下文与目标合法性由共用底层检查。模型不能修改安全配置或直接绕过保护链输出速度。

工作节点常驻，感知回调与重计算分离，复用地图距离场和相关缓存。缓存须关联配置、地图 epoch、目标与位姿适用范围。支持增量搜索游标，已有一个安全候选时也能继续检查替代方案；新 epoch 或相关地图变化后按规则重置游标。

分别记录 RPC 等待限时、规划工作截止时间、导航任务时间、无进展限时和保护反馈时限。仿真时间与墙钟时间分开。异步化不等于无限等待，超时与客户端断开后的任务归属、取消和停止必须可追踪。

### 5.2 状态与失败原因

建议状态：QUEUED → PLANNING → EXECUTING / RECOVERING → SUCCEEDED / REJECTED / ABORTED / CANCELED / TIMED_OUT。保护停车、停止确认失败单独记录，不伪装成正常取消。

固定失败枚举至少包括：

| 枚举 | 含义 |
|---|---|
| GOAL_INVALID / GOAL_IN_COLLISION | 输入非法或目标车体不合法 |
| NO_PATH | 本次配置与搜索范围下没有规划解，不证明全局不存在路径 |
| UNKNOWN_SPACE_BLOCKED | 所需运动包络涉及未确认自由空间 |
| PATH_INVALIDATED | 更新后实际路径条件失效 |
| PLANNING_DEADLINE / EXECUTION_TIMEOUT / NO_PROGRESS | 区分规划计算、执行时间与运动无进展 |
| COLLISION_MONITOR_STOP | 实时保护触发，保留区域和传感器证据 |
| SENSOR_STALE / LOCALIZATION_UNAVAILABLE | 反馈时序或定位不满足执行条件 |
| CONFIG_MISMATCH / MAP_EPOCH_CHANGED | 参数或定位地图上下文不兼容 |
| OPERATOR_STOP / BUDGET_EXHAUSTED / CANCELED | 明确任务终止 |
| STOP_UNCONFIRMED | 无法确认取消或停稳，禁止提交后续运动 |

每个结果带 source、原始 Nav2 错误码、时间戳、可恢复标志、恢复次数、配置哈希、地图/路径标识与停车证据。MAP_UPDATED、候选等待中和 RPC_TIMEOUT 应作为事件或通信状态，不自动成为“车辆不可达”的终态枚举。

### 5.3 恢复与停止

采用 Nav2 行为树管理重规划、等待和受保护恢复；恢复次数、时间及失败额度有上限。清理 costmap 只能清理可重建的观测层，不得借清图消除真实静态障碍、未知空间限制或保护触发。

临时障碍解除后可以在授权额度内恢复；操作员停止、反馈失效及停止未确认不能由模型自动恢复。失败记忆按原因、目标、地图上下文和有效期关联，避免一次暂时失败永久封锁整个区域，也避免无限重发同一失败动作。

传统阶段无有效目标时，保持零速并完成有界补查；符合阶段切换条件则交接 AI，不直接报告全局探索完成。AI 阶段根据观测、尝试记录和执行反馈继续残余任务；终止需明确记录任务完成依据、预算耗尽、充分尝试后受阻或外部停止。紧急停止和操作员停止立即生效，不经过探索复查。

## 6. 整体改造与代码映射

以下工作形成同一个可运行版本，不按“每项先验收，再允许下一项”的方式拆成多轮实验：

| 工作包 | 交付内容 | 拟涉及现有位置 |
|---|---|---|
| 证据与版本 | 保留原日志、配置、地图与源码哈希；独立实现分支 | docs/experiments、provenance/账本 |
| 最小共用安全 | 单一车辆契约、真实 footprint、必要误差、统一输出保护链；移除重复保守门槛 | navigation/nav2.yaml、safety_contract.py、velocity_guard.py、bringup |
| 标准导航与恢复 | 适配规划/控制、地图更新重规划、受保护有界恢复 | exploration/path_safety.py、observation.py、Nav2 配置 |
| 异步 MCP 与操作模式 | 地图查看、路径查询、新目标/途经点导航、状态、取消、恢复；固定失败枚举 | robot_skills/api.py、store.py、supervisor.py、ros_worker.py、robot_agent/mcp_skills_server.py |
| 两阶段任务编排 | 传统算法独立探索 → 状态交接 → AI 持续操作；去掉三动作上限 | exploration/frontier.py、aggressive.py、robot_skills/regional.py、robot_agent/run_loop.py |
| 整场评估 | 多回合仿真、固定覆盖率分母、阶段快照、真值轨迹与停止原因 | 仿真运行脚本、独立评估器、实验报告 |

先完成可运行的集成版本，必要启动检查与已有回归随版本执行，随后直接运行完整探索回合。保留配置和阶段计时，便于从实际失败定位几何、控制、调度或高层操作问题；不继续靠逐个增加阈值和接口限时维持旧流程。

## 7. 多轮端到端仿真与评价

### 7.1 运行方式

每回合从一致的初始位姿和在线建图条件开始，记录代码版本、车辆契约、传感器、场景、随机种子、预算与时间基准。先运行传统探索，达到切换条件后保存阶段快照并交接 AI，AI 继续到整场终态。不得在交接时给 AI 额外全图或真值位姿。

多轮覆盖当前地图与走廊/隘口更丰富的地图；直接观察完整系统能否持续运行、是否补足剩余未知区域。回合数量和时间/距离预算在运行配置中明确，不再以固定三个目标代替完整任务。

启动前自动检查配置一致性、反馈新鲜度、导航接口和停止链。既有直通道、转弯、厘米级起点连接、未知包络、临时障碍、地图更新、超时和取消案例保留为回归与诊断工具，不要求每种局部动作先做五次独立实验才开始整场运行。真实碰撞、失控或保护失效立即结束该回合并记录，不带病续跑。

除 Nav2 action 状态外，保存真实轨迹、车体是否越过入口、接触事件与车体间距。雷达最近距离不等于车体间距。仿真真值仅进入独立评估器，不能提供给算法、模型或控制器。

### 7.2 主要指标：最终地图探索覆盖率

固定评估区域和网格分辨率，用独立仿真环境定义可达区域内可观测自由空间的评估分母，单独列出不可达/不可观测部分。该分母在同场景比较中保持一致，不能用机器人当前已知面积充当总面积。

记录：

| 指标 | 定义与用途 |
|---|---|
| C_init | 出生后初始化扫描覆盖率，单独记账 |
| C_handoff | 传统阶段结束、AI 接入时的覆盖率 |
| C_final | 整场结束覆盖率，主要评价结果 |
| ΔC_AI | C_final − C_handoff，AI 阶段补充的覆盖率 |
| 未探索分布 | 最终未知区域的位置、遮挡与通行尝试证据 |

覆盖率来自真实观测与一致坐标下的地图对应，不能把模型猜测算作已探索。没有可靠对应或固定分母时，相应指标记为 null，不凭地图窗口面积或截图宣称完整覆盖。约 159 m² 的历史初始化面积不计作自主移动新增成果。

ΔC_AI 表示接入后的阶段增量；它包含额外运行时间和导航资源的作用，不能单凭该数值证明模型相对传统算法的因果优势。如需比较优势，在同场景、同起点、同总预算下增加传统算法全程运行对照，但不把这项研究对照作为集成仿真的前置门槛。

### 7.3 结果有效性与诊断

最终探索度决定主要效果评价。碰撞、失控、停止链失效或异常退出使该回合不能作为系统可用的成功结果，即使地图覆盖率很高。保留所有失败回合，避免只报告成功样本。

耗时、里程、无进展次数、恢复耗时、入口通过情况、候选计算和模型调用耗时、停止原因作为辅助诊断：解释覆盖率为什么低、时间在哪里消耗，服务下一轮修复，不替代主要结果。

## 8. 下一步交付与完成定义

下一步交付是一个包含共用最小安全、异步 MCP、传统探索与后期 AI 操作的集成版本，以及多轮完整仿真报告。运行代码提交与本文方案提交分开记录。

实施顺序：

1. 保存现有证据，在实现分支统一底层车辆契约、导航与保护逻辑。
2. 扩充 MCP 操作能力，接入两阶段编排，移除三目标限制并配置整场预算。
3. 执行必要启动检查后，直接运行多轮完整仿真，保存交接前后地图与轨迹。
4. 以最终覆盖率及 AI 阶段增量评价结果，根据真实停滞、拒绝、控制和调度失败集中修复，再复跑。

完成标准是系统能够连续完成前期算法探索与后期 AI 操作，阶段交接可追踪，合法通行不被重复规则误拒绝，实际不可行动作由共用底层正确阻止，终止原因明确，并提供可信的最终覆盖率。目标是用完整运行结果判断可用性，避免停留在逐次“可行性”讨论中。

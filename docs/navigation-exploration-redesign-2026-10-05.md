# 导航、实时保护与探索决策系统改进方案

日期：2026-10-05  
状态：设计方案，待分阶段实现与验收。本文发布不代表运行配置或安全逻辑已切换。  
审查基线：[aca2bde](https://github.com/huam54925-cpu/ros2-gazebo-robot-lab/commit/aca2bde014f2d1ac7e005b1b76c1a38f4a3a05b5)。

## 1. 目标与结论

目标是扩大合法路径上的探索能力，让车辆能够持续导航、遇到暂时问题后有界恢复，并准确解释停止原因。保留最少且可验证的硬约束：真实车体与必要误差包络不碰撞、运动可执行、所需自由空间已确认、反馈有效、指令受控、操作员停止始终有效。

当前问题不是单纯缺少探索意愿。候选粗筛、假设转向、实时保护、地图版本一致性、接口限时及信息收益被叠加为运动前置条件，出现“底层有可行路径，上层未能提供或执行目标”的情况。重构应统一安全依据并明确职责，避免继续增加相互不一致的阈值。

监控从固定大圆距离规则迁移到车体与运动相关的实时保护，监控始终运行。Nav2 规划器和控制器的在线碰撞检查必须保留；Collision Monitor 是独立保护层，不能替代规划可行性、局部轨迹检查或未知空间准入。

本文定义实施目标和验收门槛，不承诺未经实验的安全保证、性能倍数或整屋覆盖率。

## 3. 职责分层

| 层级 | 组件 | 负责 | 输出 |
|---|---|---|---|
| 感知与状态 | 雷达、里程计、TF、SLAM Toolbox | 地图、位姿、时序和健康状态 | 带时间戳与质量状态的数据 |
| 实时保护 | Nav2 Collision Monitor、命令 watchdog、停止仲裁 | 实时减速、停车、反馈失效处理、操作员停止 | 受保护的速度输出、触发原因 |
| 导航 | Nav2 规划器、控制器、行为树 | 可执行路径、在线碰撞检查、跟踪、重规划和有界恢复 | action 状态、进度、结构化失败 |
| 探索 | Frontier 检测、目标评价、目标记忆 | 未知边界、信息代理、到访记录、替代目标 | 候选目标与成本 |
| 任务管理 | Robot Skills、任务存储与 supervisor | 幂等、单任务仲裁、异步工作、预算、取消与终态 | task_id、状态与结果 |
| 高层决策 | 经典策略或可选大模型 | 目标优先级、任务解释、换方向与调整偏好 | 受约束的目标选择与策略 |

大模型不计算实时碰撞、不签发几何许可、不修改保护参数、不解除停止锁。几何与运动许可由确定性导航系统执行。

指定目标导航以到达目标为完成条件，途中的信息代理为零不构成终止原因。自主探索才比较信息收益与成本。模型可以建议换方向、接受较低收益或较长路径；预算调整必须符合已有任务授权，不得以“降低要求”为理由降低物理保护条件。

日常探索可以由传统 Frontier 策略持续运行。模型在存在目标优先级选择、任务语义或失败后的策略分歧时介入；其调用不阻塞实时保护或局部控制。

## 4. 统一判定与保护规则

### 4.1 单一参数源

拟新增 workspace/navigation_base/config/robot_contract.yaml，作为配置生成与校验入口；该文件路径是实施计划，不是当前已经存在的运行配置。

集中描述车体多边形及参考坐标、运动模型、已验证速度与加减速度范围、传感器坐标关系、时间基准、保护所需误差与时延预算。生成 Nav2、监控、任务接口及离线验收所需参数，并记录 contract_version 与摘要哈希。

物理参数共用，但各层派生的判定不同：车体碰撞包络、路径偏好代价和速度相关停车区有不同用途，不能继续统一成一个距离常数。不得把定位协方差直接等同于可靠误差上界；应结合对照轨迹与时序实测标定。

按既有配置，最大车宽约 1.92 m，另有每侧 0.05 m padding，直行名义宽度至少约 2.02 m，尚未含其他跟踪误差。因此 2.0 m 通道不应被要求通过。低速能减少制动相关余量，不能缩小车体或消除定位误差。

### 4.2 硬约束与软偏好

| 内容 | 处理方式 |
|---|---|
| 车体及必要误差包络与障碍相交 | 硬拒绝，由规划、控制与保护共同覆盖 |
| 运动模型不可执行或旋转时车尾碰墙 | 硬拒绝对应动作，寻找其他轨迹 |
| 所需运动包络侵入未确认自由空间 | 不执行该段；重新观察或选可确认的接近目标 |
| 靠墙、转向次数多、路线较长 | 在合法轨迹中用代价评价 |
| 中转点即时信息收益低 | 与远端可达信息、成本和任务目的比较，不作为几何拒绝 |
| 地图版本变化 | 触发相关复核或重规划，不单凭版本不同永久作废 |
| 查询接口等待超时 | 返回等待状态或传输错误，不等同于无路径 |
| 任务明确预算耗尽、操作员停止、反馈失效 | 对应终止或停车，保持结构化原因 |

未知不是确认障碍，也不能默认为可行驶自由空间。地图尚未确认的部分可以成为观察对象，车体不能凭空穿入未知区域。

窄通道中不默认调用原地旋转恢复；若具体旋转运动包络通过检查，可允许相应角度。禁止的是不可行的动作，不是区域名称或所有转向。

### 4.3 Nav2 与实时保护

优先评估 Smac State Lattice 的差速控制集与完整车体碰撞检查。选择理由是该车辆非圆形且存在参考点偏置，需要位置、朝向和运动模型共同参与规划。先保留 Regulated Pure Pursuit 作为控制基线，验证它对规划动作的跟踪一致性；后续控制器替换应单独做对照。

采用 inflation 代价引导合法路径居中，保留碰撞相关的不可通行条件。不能将所有膨胀成本软化，也不能靠提高 inflation 参数保证窄通道通过。

Collision Monitor 使用原始实时扫描和正确 TF，评估多边形停车区、速度相关区域与基于预计碰撞时间的减速。必要保护同时覆盖旋转时车尾扫掠、倒车与传感器盲区。保护参数由制动、时延、定位及跟踪误差标定；不直接沿用示例默认值。

保持操作员停止、命令失效停车、传感器/TF 失效处理及单一速度输出仲裁。控制器与恢复行为必须经过同一保护链，防止任一路径绕过监控。停止确认结合取消终态与新鲜速度反馈，不能仅发送一次零速度就报告已停。

现有自定义精确检查先用于对照。仅当 Nav2 配置与控制轨迹已证明覆盖对应约束后，才将重复在线硬门降为只记录结果的影子检查；若存在缺口，应保留范围明确的检查或实现标准插件。任何切换都要记录新旧判定分歧，不能留下未知空间或整车运动的保护空缺。

## 5. 异步任务与可恢复流程

### 5.1 接口契约

现有运动执行已经有 task_id、幂等和任务存储，优先复用，不重新创建另一套任务系统。新增异步候选搜索，消除候选完整检查占用一个长时间同步 MCP 请求的问题。

| 拟定接口 | 输入概要 | 输出与语义 |
|---|---|---|
| start_candidate_search | request_id、mission_id、搜索范围与资源预算 | 立即返回 search_id，后台增量工作 |
| get_candidate_search_status | search_id | 阶段、已查/待查数量、候选、搜索是否完成 |
| submit_navigation | request_id、mission_id、goal_id 或已授权的指定目标 | task_id；接收不代表许可或成功 |
| get_task_status | task_id | 状态、阶段、进度、健康状态与失败详情 |
| cancel_task | task_id、request_id | 取消请求状态，最终确认另行查询 |
| stop_robot | request_id | 高优先级停止并禁止旧任务继续输出；确认停止后返回证据 |

上述名称是设计接口，需与现有 API 兼容映射。指定坐标导航仅面向本地授权任务；模型仍从候选 ID 选择，不因重构自动获得任意坐标或速度权限。

工作节点常驻，感知回调与重计算分离，复用地图距离场和相关缓存。缓存须关联配置、地图 epoch、目标与位姿适用范围。支持增量搜索游标，已有一个安全候选时也能继续检查替代方案；新 epoch 或相关地图变化后按规则重置游标。

分别记录 RPC 等待限时、规划工作截止时间、导航任务时间、无进展限时和保护反馈时限。仿真时间与墙钟时间分开。异步化不等于无限等待，超时与客户端断开后的任务归属、取消和停止必须可追踪。

### 5.2 状态与失败原因

建议状态：QUEUED → PLANNING → EXECUTING / RECOVERING → SUCCEEDED / REJECTED / ABORTED / CANCELED / TIMED_OUT。保护停车、停止确认失败单独记录，不伪装成正常取消。

固定失败枚举至少包括：

| 枚举 | 含义 |
|---|---|
| GOAL_INVALID / GOAL_IN_COLLISION | 输入非法或目标车体不合法 |
| NO_PATH | 本次配置与搜索范围下没有规划解，不证明全局不存在路径 |
| UNKNOWN_SPACE_BLOCKED | 所需运动包络涉及未确认自由空间 |
| PATH_INVALIDATED | 更新后实际路径条件失效 |
| PLANNING_DEADLINE / EXECUTION_TIMEOUT / NO_PROGRESS | 区分规划计算、执行时间与运动无进展 |
| COLLISION_MONITOR_STOP | 实时保护触发，保留区域和传感器证据 |
| SENSOR_STALE / LOCALIZATION_UNAVAILABLE | 反馈时序或定位不满足执行条件 |
| CONFIG_MISMATCH / MAP_EPOCH_CHANGED | 参数或定位地图上下文不兼容 |
| OPERATOR_STOP / BUDGET_EXHAUSTED / CANCELED | 明确任务终止 |
| STOP_UNCONFIRMED | 无法确认取消或停稳，禁止提交后续运动 |

每个结果带 source、原始 Nav2 错误码、时间戳、可恢复标志、恢复次数、配置哈希、地图/路径标识与停车证据。MAP_UPDATED、候选等待中和 RPC_TIMEOUT 应作为事件或通信状态，不自动成为“车辆不可达”的终态枚举。

### 5.3 恢复与停止

采用 Nav2 行为树管理重规划、等待和受保护恢复；恢复次数、时间及失败额度有上限。清理 costmap 只能清理可重建的观测层，不得借清图消除真实静态障碍、未知空间限制或保护触发。

临时障碍解除后可以在授权额度内恢复；操作员停止、反馈失效及停止未确认不能由模型自动恢复。失败记忆按原因、目标、地图上下文和有效期关联，避免一次暂时失败永久封锁整个区域，也避免无限重发同一失败动作。

探索模型建议 STOP 且搜索未完成时，保持零速，补查有限数量的替代候选并刷新预算，再确定探索终止原因。紧急停止和操作员停止不经过该复查。

## 7. 验收方案

### 7.1 几何与指定目标导航

| 案例 | 应验证的结果 |
|---|---|
| 2.0 / 2.2 / 3 m 直通道 | 根据真实轮廓与余量明确拒绝或通过，不强迫所有宽度成功 |
| 3 m / 5 m 原地转向 | 验证全过程扫掠，允许合法角度、拒绝实际碰撞角度 |
| 90° 与 180° 路线 | 验证转弯姿态、曲线/倒车策略与控制器执行一致 |
| 厘米级起点连接与真正掉头 | 排除虚构大转身，同时保留真实掉头碰撞检查 |
| 墙内目标与未知包络 | 拒绝准确，车辆不因错误目标产生未授权运动 |
| 临时障碍出现、移除、持续堵塞 | 减速/停车正确；有界恢复或明确退出 |
| 地图不断更新、SLAM 修正、TF 过期 | 相关路径及时更新，避免无限作废；反馈失效可停 |
| 查询超时、进程退出、重复请求、取消 | 任务可追踪、无重复运动、停止证据完整 |

先在已知测试地图中验证指定目标导航，再重置 SLAM，仅用本次传感器在线观测验证探索。导航单次成功不等于持续探索通过。建议静态正向案例每项至少 5 次重复并全部达到约定终点与停稳标准；动态与故障案例验证预期保护/恢复终态。未通过项目保留为未通过，不用平均指标掩盖。

验收除 Nav2 action 状态外，记录实际轨迹、完整车体是否越过入口、方向误差、接触事件和车体到障碍距离。最近雷达距离不等于车身边缘间距。仿真真值只进入独立评估器，不提供给模型、探索选点或路径控制。

### 7.2 探索对照

同一场景、初始位姿、传感器、导航与保护配置、资源预算下，至少比较传统 Frontier 与 Frontier + 模型；建议 5 次配对运行。先小型通道地图，再增加长走廊、多入口、死胡同、环路和临时障碍。

指标包括可达区域观测比例、目标成功率、入口通过率、无进展次数、恢复时间、实际里程、候选计算延迟、模型延迟/调用成本、停止原因分布。明确统计分母与可达/可观测区域定义。

初始化静止建图面积单独记账。无有效地图配准或观测证据时，可信收益保持 null；原始地图窗口变化只作诊断。严格因果收益需要独立方法，不用 Δknown 自动替代。未配置完整评估区域时不宣称整屋覆盖率。

## 8. 本轮优先交付与完成定义

第一轮实现优先交付：

1. 统一车辆契约、参数生成及实际读取一致性校验。
2. 新导航/保护链的纯导航验证，保留本次通道几何作为回归。
3. 异步候选搜索原型、持久化任务状态、阶段计时与固定失败枚举。

随后完成有界恢复、传统探索基线和模型对照。大模型的增益在相同稳定导航底座上评价，不将基础导航失败归因于高层能力。

完成重构需要证明：几何与运动合法的测试路线能持续执行；确实不可行的动作被正确拒绝；临时问题可以在预算内恢复；取消、反馈丢失和操作员停止有效；探索搜索与收益选择不冒充碰撞原因。扩大探索能力必须由实跑对照支持。
